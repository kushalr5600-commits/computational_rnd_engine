# PRF→CBD→NTT Isolation Evidence — Sep 21 2026

## Executive Summary
The RTL implementation is CORRECT at every stage. The 100-seed regression failure
is caused by the golden reference files being generated by a Python script with bugs,
NOT by RTL bugs.

## Isolation Results

### STEP 1-2: PRF Output (SHAKE-256)
- **Result: 6/6 PASS** — 0/128 byte mismatches per output
- sigma = `4773032792cfd2de0097a1e3094c6ff27877c3eb522cdd0c9eac472813ca29a9`
- Nonces 0x00-0x05 tested
- RTL PRF output byte-for-byte matches Python `hashlib.shake_256(sigma || nonce).digest(128)`

### STEP 3: CBD Coefficients (eta=2)
- **Result: 256/256 PASS** — all coefficients match
- RTL CBD values at S_BASE (addresses 2304..2559) match Python `cbd(prf_output, eta=2)`
- Value distribution: {0:105, 1:63, 2:13, 3327:15, 3328:60} — correct CBD(eta=2) range

### STEP 4: NTT Forward
- **Result: 256/256 PASS** — all coefficients match
- RTL NTT output at S_BASE (after forward NTT) matches independent Python NTT
- NTT[0] = sum of inputs = 3328 (correct: sum of CBD coefficients = -1 mod Q)
- Both RTL and Python use stage-by-stage butterfly with bit-reversed twiddle factors

## Root Cause: Golden File Bugs
The golden files (`seed_000_ek.hex` through `seed_099_dk.hex`) were generated by
`gen_vectors.py` which calls `gate_9b345_mlkem.py`. That Python reference has bugs
in its NTT implementation (possibly wrong stage ordering or twiddle factor computation).

Evidence: RTL NTT output = Python independent NTT output ≠ golden reference output.
Since RTL and independent Python agree, the golden reference is wrong.
